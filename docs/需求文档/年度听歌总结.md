# 年度听歌总结（独立多屏叙事）

> 状态：已实现（2026-11-12）
> 日期：2026-11-12
> 关联决策：独立入口 + 多屏滚动叙事（在「同款卡片年度版 / 年度版+年度之最 / 独立多屏总结」三选一中选定工作量最大的第三种）
> 实现现状见：docs/功能规格/年度听歌总结.md

---

## 1. 用户场景（一句话）

年末（或任何时候）想回顾自己这一年听了多少音乐、最爱谁、循环哪首、哪一天听得最疯，点侧边栏「年度总结」后，像看一支短片一样一屏一屏往下翻完整个 2026 年。

## 2. 数据流

### 数据来源

唯一的原始数据是 `play_logs` 表（`user_id, name, singer, album, album_mid, duration, played_sec, played_at`），索引 `idx_play_logs_user(user_id, played_at)` 已覆盖按时间范围扫描。

### API（新增，server/routes/stats.js）

`GET /api/stats/yearly?yearOffset=0`

- `yearOffset=0` → 当前自然年（1/1 00:00 至今）；`1` → 去年（1/1~12/31）；上限 10。
- 一次请求返回整页所需全部数据（多屏共用一份，避免 8 次并发请求）。

```jsonc
{
  "year": 2026,
  "label": "2026 年",
  "hasData": true,                    // false 时前端只显示空态屏
  "overview": {
    "plays": 0, "sec": 0, "uniqueSongs": 0, "uniqueArtists": 0,
    "days": 0, "newSongs": 0
  },
  "monthly": [{ "month": 1, "plays": 0, "sec": 0 }],   // 固定 12 项，无数据补 0
  "topSongs":   [{ "name": "", "singer": "", "album": "", "album_mid": "", "play_count": 0, "total_sec": 0 }],  // 10
  "topArtists": [{ "singer": "", "singer_mid": "", "play_count": 0, "total_sec": 0 }],                         // 5，复用 aggregateArtists + attachSingerMids
  "topAlbums":  [{ "album": "", "singer": "", "album_mid": "", "play_count": 0 }],                             // 4，复用 fillAlbumCoverMids 补封面
  "highlights": {
    "bestDay":    { "day": "2026-03-14", "plays": 0 },      // 单日最高播放；无数据为 null
    "streak":     { "days": 0, "start": "", "end": "" },    // 最长连续听歌天数
    "peakMonth":  { "month": 10, "plays": 0 },              // 最常听的月份
    "lateNight":  { "hour": 2, "plays": 0 },                // 深夜（0-4 点）播放最多的时刻；无则 null
    "repeatRate": 0, "skipRate": 0,
    "completion": { "low": 0, "mid": 0, "high": 0 }
  }
}
```

### 聚合口径

- `overview`：`COUNT(*)`、`SUM(played_sec)`、`COUNT(DISTINCT name||singer)`、`COUNT(DISTINCT date(played_at/1000,'unixepoch','localtime'))`。
- `newSongs`：年内首次出现（该 user 在 yearStart 之前从未播放过）的 `name__singer` 数量。
- `streak`：取年内所有 `DISTINCT date`，在 JS 里按天排序后算最长连续段。
- `topAlbums` 的 `album_mid` 使用「组内第一个有效 mid」并做反查补全（与月报同一套逻辑，见功能规格/数据统计指标优化.md）。
- `lateNight`：只统计 0-4 点（含 4 点），取播放次数最多的小时；全为 0 时返回 null。

### 空值 / 异常

- 年内无任何播放记录 → `hasData: false`，前端渲染单一空态屏（「2026 年还没有听歌记录」+「去听歌」按钮）。
- 接口失败 → `#main` 显示「加载失败：xxx」，提供「重试」按钮（复用 report.js 的错误文案风格）。
- 某一块数据为空（如没有收藏、没有专辑）→ 该屏内部显示「暂无」，不隐藏整屏，保证叙事连贯。

## 3. 状态机

页面级：

```
进入（navYearly 点击 / 历史恢复）
  → loading（「正在整理你的 2026…」）
  → hasData=false → empty
  → hasData=true  → ready（第 1 屏）
```

`ready` 内部：

- 当前屏 `activeIndex ∈ [0, 7]`，滚动吸附驱动；右侧圆点与屏号同步。
- 年份切换：`yearOffset` 变化 → 回 loading → ready/empty，滚动位置重置到第 1 屏。
- 年份切换按钮：更早年份无数据时仍可切换（显示空态），但不能超过 10 年、不能向未来（`yearOffset >= 0`）。
- 屏幕切换动画：`IntersectionObserver` 到 60% 视为进入，加 `.in` 类触发 CSS 动画；只触发一次（离开不撤销），避免滚动抖动时反复播放。

并发：切换年份时若上一次请求仍在飞，用自增 `seq` 丢弃陈旧响应（与歌词/播放的既有做法一致）。

## 5. 边界与失败

- **只有几个月数据**：月度柱状图按 12 项补 0，不缩放；封面屏仍显示「2026 年」。
- **跨年边界**：`yearOffset=0` 的 end 用 `Date.now()`（不是 12/31），避免显示未来空白月份为「已结束」。
- **时区**：所有 `date()` 聚合都用 `'localtime'`，与播放器上报的 `played_at` 一致；前端不自行按 UTC 换算。
- **超长列表**：歌手 5、歌曲 10、专辑 4，均有上限。
- **移动端**：每屏 `min-height: 100%`，内容超高时该屏内部滚动（`overflow-y: auto`），不破坏 scroll-snap。
- **反查超时**：`topAlbums` 的 mid 反查沿用 1.5s 超时 + 缓存，失败则该专辑显示占位图。

## 6. 备选方案

| 方案 | 为什么没选 |
|------|-----------|
| 同款卡片的年度版（加「本年」tab） | 改动最小，但和月报在信息结构上完全重复，年度缺少仪式感 |
| 年度版 + 年度之最卡片 | 有增量信息，但仍塞在统计页的卡片墙里，阅读节奏和月报挤在一起 |
| **独立多屏叙事（选定）** | 独立的滚动叙事、每屏一个主题、数据密度低、视觉冲击强；代价是新增一个页面级模块和约 300 行 CSS，但不动既有报告逻辑，回归风险低 |

## 7. 验收标准

1. 侧边栏点「年度总结」→ 进入独立页面，首屏显示「2026 年」和年度总播放次数，向下滚动可依次看到 8 个屏，右侧圆点随滚动高亮。
2. 点右上角「‹」切到 2025 年 → 若该年无记录，整页显示「2025 年还没有听歌记录」；点「›」回到 2026 年数据恢复。
3. 「年度之最」屏的「单日最高播放」日期与次数，和月报/趋势图能对得上（抽查某一天）。
4. 断网后进入该页面 → 显示「加载失败」+ 重试按钮，不白屏。
5. 390px 手机宽度下每屏内容不横向溢出，文字不重叠；返回其它视图后 `#main` 的内边距与滚动恢复正常。
