# 拔耳机自动暂停

> 状态：已实现（2026-11-06）
> 实现现状见：docs/功能规格/拔耳机自动暂停.md
> 日期：2026-11-06
> 关联决策：多信号并集检测 + 复用 `timerPaused` 兜底 + 默认开启的设备本地开关 + 不自动恢复

---

## 1. 用户场景（一句话）

用户戴着有线耳机听 WeMusic，拔掉耳机时不希望音乐突然从扬声器外放，希望播放立即自动暂停，之后由自己决定何时继续。

## 2. 数据流

### 信号来源（没有服务端数据，全部是浏览器本地事件）

| 信号 | 来源 | 覆盖场景 |
|------|------|---------|
| `devicechange` | `navigator.mediaDevices` | USB / 蓝牙音频设备移除、带麦克风耳机拔出 |
| `sinkchange` | `AudioContext`（Chrome / Edge） | 输出路由变化、系统默认输出设备被切换 |
| `statechange → interrupted` | `AudioContext` | Safari / iOS 的音频会话中断 |
| 非预期 `pause` | `<audio id="audio">` | 浏览器在设备拔出时直接把媒体元素暂停（Safari / iOS 常见） |

四个信号都汇入同一个幂等入口 `pauseForAudioDevice(source)`，不做任何设备枚举比对。

### 为什么不比对 `enumerateDevices()`

2026-11-06 在本机 Chrome（localhost 安全上下文、未授予麦克风权限）实测：

```json
{ "secure": true, "hasMD": true, "hasSinkId": true, "sinkId": "",
  "hasOnSinkChange": true, "outputs": [
    { "deviceId": "", "groupId": "", "label": "" }
  ] }
```

无权限时 `audiooutput` 只返回一个 `deviceId` / `groupId` / `label` 全为空的匿名占位设备，插拔前后快照完全一致，既无法判方向也无法判有无设备消失。且 macOS 的 3.5mm 耳机只是内置声卡的一个 jack，不是独立枚举设备，设备列表本来就可能不变。因此「快照比对」方案实测证伪，废弃。

### 处理链路

```
浏览器信号
  → shouldPauseForDeviceSignal()（开关 / 正在播放 / 3 秒冷却）
  → pauseForAudioDevice()
      ├─ timerPaused = true（关键：抑制所有自动恢复路径）
      ├─ bgAudio.pause()（bg 模式）或 iframe 静音（iframe 模式）
      ├─ 播放按钮图标 / title / MediaSession 状态同步
      └─ toast 提示 + 控制台 [audio-device] 日志
```

### 空值与异常

- `navigator.mediaDevices` 不存在（非安全上下文 / 老浏览器）→ 跳过该信号绑定，其余信号照常工作。
- `AudioContext` 不支持 `sinkchange` / `interrupted` → 用 `'onsinkchange' in ctx` 等能力检测跳过，不抛异常。
- 开关读取失败（localStorage 被禁用）→ 用 `try/catch` 包住读取，回退为默认开启。
- 没有任何信号（浏览器完全不暴露设备变化）→ 行为退化为现状（继续播放），这是平台限制，不是错误态；文档给出真机自检方法。

## 3. 状态机

### 播放状态

```
播放中（timerPaused=false, _devicePaused=false）
  │
  ├─ 设备信号到达 + 开关开启 + 3 秒内未暂停过
  │      → 已因设备暂停（timerPaused=true, _devicePaused=true）
  │            ├─ bg 模式：bgAudio.pause()，声音立即停止
  │            └─ iframe 模式：postMessage 把 B 站播放器音量设为 0
  │
  └─ 用户主动暂停 → 普通暂停态（_devicePaused=false），与设备无关

已因设备暂停
  ├─ 用户点播放 / 按空格 / MediaSession play
  │      → 恢复播放；若 iframe 曾被静音则恢复原音量；_devicePaused=false
  ├─ 用户切歌 / 换源 → 重置进度时清除设备暂停标记，按新歌正常起播
  └─ 插回耳机 → 不自动恢复（保守默认）
```

### 互斥与并发

- 同一轮插拔常常连续触发 `devicechange` + `sinkchange` + `pause`：250ms 防抖合并事件类信号，3 秒冷却窗口保证只暂停一次、只 toast 一次。
- 快速连续暂停/播放：冷却窗口只拦「设备信号」，不拦用户主动操作。
- 暂停后 1 秒内的 `_tick()`：因为 `timerPaused=true`，`_tick()` 首行直接 return，不会把 `bgAudio.play()` 置回来。
- crossfade 期间收到设备信号：仍允许暂停，但 `timerPaused=true` 会让淡入淡出接管流程一并停住；恢复播放时由用户主动触发，不产生双声道。

## 5. 边界与失败

- **插入耳机 / 插入 USB 麦克风也触发 `devicechange`** → 会误暂停一次。这是有意取舍：漏判导致外放的代价远大于多点一次播放；设置项文案明确告知「拔出或切换音频输出设备时」。
- **播放尚未开始 / 已由用户暂停 / 无当前歌曲** → 一律不处理，避免加载期误判。
- **展开视频（iframe）模式** → B 站官方 postMessage 只公开了 `setVolume`，无法远程暂停播放器。采取「计时器暂停 + 音量置 0 + 提示用户手动暂停」，保证不外放；恢复时还原音量。
- **系统睡眠 / 音频驱动重启** → 可能误暂停一次，冷却窗口限制为一次。
- **Firefox / Safari 桌面** → 缺 `sinkchange`；仍可能由 `devicechange`、`interrupted`、媒体元素 `pause` 覆盖，但不承诺 100% 可靠。纯 Web 无法直接读到「3.5mm 插头被拔出」这一物理事件，这是平台能力边界。
- **降级方案** → 关闭设置开关即完全恢复原有行为，无需重启页面。

## 6. 备选方案

| 方案 | 为什么没选 |
|------|-----------|
| A. `devicechange` + `enumerateDevices()` 快照比对，只在「输出设备减少」时暂停 | 本机实测无麦克风权限时只返回一个全空匿名设备，快照恒等；3.5mm 耳机也不是独立设备。已证伪，且会诱导申请麦克风权限（为检测耳机而申请录音权限，侵入性过高） |
| B. 只调 `bgAudio.pause()`，不动 `timerPaused` | `_tick()` 每秒巡检到「意外暂停」会在 1 秒内 `play()` 回来，功能完全失效；5 秒健康检查、收起视频续播、卡顿恢复也都会把声音放回来 |
| C. 新增独立 guard 标志，在所有 10+ 处自动恢复路径逐一加判断 | 与 B 等价但改动面大、易漏；`timerPaused` 本来就是现成的、被所有路径认可的「用户暂停」语义，复用它最小且最稳 |
| D. 申请麦克风权限以读取设备 label 判断方向 | 为一个防外放功能索要录音权限，权限收益与隐私成本不匹配；且仍解决不了 3.5mm 场景 |
| E. 打包成 Electron / 原生客户端用系统 API 精确检测 | 架构级变更，超出本次范围；当前项目是纯 Web 应用 |
| F. 插回耳机自动恢复播放 | 用户没要求，且「突然出声」和「突然外放」一样容易造成惊吓；保守默认不自动恢复 |

选择「多信号并集 + 复用 `timerPaused`」的代价是插入音频设备时可能多暂停一次，换来的是跨平台最大覆盖，且不触碰任何现有恢复路径的判断逻辑。

## 7. 验收标准

1. 用户打开页面播放一首歌 → 拔掉有线耳机 → 声音立即停止，播放按钮变为「播放」状态，出现「耳机已拔出，已暂停播放」提示。
2. 拔耳机后不碰任何按钮，等待 5 秒以上 → 播放仍处于暂停态，不会自己重新响起来。
3. 因拔耳机暂停后，用户点一下播放按钮 → 从原进度继续播放；若当时展开了视频，视频音量也会恢复。
4. 用户在设置面板关闭「拔耳机自动暂停」→ 再拔耳机 → 音乐照常继续播放（回到原行为）。
5. 用户没有播放任何歌曲时插拔音频设备 → 不出现任何提示，播放状态不被改变。

### 真机自检（浏览器无法自动化物理插拔）

播放中打开控制台，拔一次耳机，应看到 `[audio-device] 收到信号: xxx` 与 `[audio-device] xxx → 自动暂停` 两行日志。若只有前者没有后者，说明该信号被冷却窗口或播放条件过滤；若两者都没有，说明该浏览器不暴露任何设备变化信号，属于第 5 节的平台边界。
