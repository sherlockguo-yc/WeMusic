# 拔耳机自动暂停

> 描述当前实现的数据流、状态、边界与涉及文件。修改本功能前请先读本文档。
> 方案取舍与决策历史见 `docs/需求文档/拔耳机自动暂停.md`（已冻结）。

---

## 一、功能定义

播放中音频输出设备发生变化（拔出耳机、切换输出设备、音频会话被中断）时自动暂停，避免音乐突然从扬声器外放。默认开启，是**设备本地设置**（只存 localStorage，不进 `/api/auth/preferences`，与音量归一化、淡入淡出、EQ 一致）。

设置位置：设置面板 →「拔耳机自动暂停」开关。
localStorage key：`wemusic_headphone_pause`，`'0'` = 关闭，**未设置或 `'1'` = 开启**。

---

## 二、为什么不做设备枚举比对

2026-11-06 本机 Chrome（localhost 安全上下文、无麦克风权限）实测：

```json
{ "secure": true, "hasMD": true, "hasSinkId": true, "sinkId": "",
  "hasOnSinkChange": true, "outputs": [{ "deviceId": "", "groupId": "", "label": "" }] }
```

`enumerateDevices()` 的 `audiooutput` 只返回一个三项全空的匿名占位设备，插拔前后完全一致；且 macOS 3.5mm 耳机只是内置声卡的一个 jack，不是独立枚举设备。因此实现里**不调用 `enumerateDevices()`**，改为把四类事件并集。

## 三、数据流

```
devicechange (navigator.mediaDevices)          ┐
sinkchange   (AudioContext, Chrome/Edge)        │
statechange→interrupted (AudioContext)          ├─→ _initAudioDeviceWatch.onSignal(source)
非预期 pause  (bgAudio)                         ┘        │ 250ms 防抖（pause 路径不防抖，直接进）
                                                          ↓
                         shouldPauseForDeviceSignal()  ← src/playback-guard.js 纯函数
                           enabled / playing / 3s 冷却
                                                          ↓
                              pauseForAudioDevice(source)  ← src/player.js 幂等入口
```

`pauseForAudioDevice(source)` 依次做：

1. `timerPaused = true`（**关键**，见第五节）
2. `bgAudio.pause()`；若 `mode === 'iframe'` 则 `_setIframeVolume(0)` 并置 `_iframeMutedByDevice`
3. 播放按钮 → `PLAY_ICON`、title →「继续自动连播」
4. `navigator.mediaSession.playbackState = 'paused'`
5. toast：bg 模式「耳机已拔出，已暂停播放」；iframe 模式「耳机已拔出，视频已静音（请手动暂停）」
6. `console.warn('[audio-device] <source> → 自动暂停')`

事件监听在 `initPlayer()` 中由 `_initAudioDeviceWatch()` 注册，必须位于 `_initAudioCtx()` 之后（`sinkchange` / `statechange` 挂在 AudioContext 实例上）。能力检测：无 `mediaDevices` 或无 `'onsinkchange' in ctx` 时跳过对应绑定，不抛异常。

### 四类信号的判定条件

| 信号 | 触发条件 | 防抖 |
|------|---------|------|
| `devicechange` | 事件到达即算 | 250ms |
| `sinkchange` | 事件到达即算 | 250ms |
| `statechange` | 仅 `_audioCtx.state === 'interrupted'`；`suspended` 不处理（页面节流也会出现，会误判） | 250ms |
| `bgAudio` 的 `pause` | `isUnexpectedPause({ timerPaused, mode, crossfading, playingSeen, hasSong, paused })` 全为真 | 无，同步判定 |

`isUnexpectedPause` 排除用户主动暂停（`timerPaused=true`）、展开视频（`mode='iframe'`）、crossfade、切歌/换源/销毁（`playingSeen` 由 `_beginLoad()` 清零）、无当前歌曲。`pause` 事件异步派发，判定发生在 `togglePause()` / `expandVideo()` / `destroyVideo()` 同步改完状态位之后。

## 四、状态

| 变量 | 位置 | 含义 |
|------|------|------|
| `timerPaused` | `src/player.js` 导出状态 | 播放总开关；设备暂停置 true |
| `_devicePaused` | `src/player.js` | 当前暂停是否由设备中断触发 |
| `_iframeMutedByDevice` | `src/player.js` | iframe 是否被设备中断静音 |
| `_lastDevicePauseAt` | `src/player.js` | 冷却窗口起点 |
| `_deviceSignalTimer` | `src/player.js` | 事件防抖句柄 |

常量（`src/playback-guard.js`）：`DEVICE_SIGNAL_DEBOUNCE_MS = 250`、`DEVICE_PAUSE_COOLDOWN_MS = 3000`。

### 状态流转

```
播放中
  ├─ 设备信号 + 开关开 + 冷却已过 → 已因设备暂停
  └─ 用户点暂停 → 普通暂停态（_devicePaused=false）

已因设备暂停
  ├─ 点播放 / 空格 / MediaSession play → togglePause() → _clearDevicePause() → 恢复
  ├─ 切歌 / 换源 → resetProgress() → _clearDevicePause()
  └─ 插回耳机 → 不自动恢复
```

`_clearDevicePause()`：清 `_devicePaused`、还原 iframe 音量、`mediaSession.playbackState = 'playing'`。`togglePause()` 另外在每次切换时同步 `playbackState`（此前只在 `updateMediaSession()` 里设过 `'playing'`，暂停时从未设为 `'paused'`）。

## 五、为什么必须置 `timerPaused`

`_tick()` 每秒执行，发现 `bgAudio.paused && _hasStartedPlaying && !_crossfading` 就 `bgAudio.play()` 恢复；此外 5 秒健康检查、加载看门狗、卡顿恢复、收起视频续播都会重新起播。**只调 `bgAudio.pause()` 会在 1 秒内被放回来。**

`timerPaused` 是这些路径共同认可的现成开关（`_tick()` 首行即 return），因此实现不改任何现有恢复路径的判断逻辑，只增加一个写入方。参见 `docs/功能规格/后台播放.md` 第五章。

## 六、边界与平台覆盖

| 场景 | 行为 |
|------|------|
| 插入耳机 / 插入 USB 麦克风 | `devicechange` 同样触发，会多暂停一次（有意的保守取舍） |
| 未播放 / 已暂停 / 无当前歌曲 | 不处理，不弹提示 |
| 同一轮插拔多个信号接连到达 | 防抖 + 3 秒冷却，只暂停一次、只提示一次 |
| 展开视频（iframe） | B 站官方 postMessage 只公开 `setVolume`，无法远程暂停；采取静音 + 停计时器 + 提示用户手动暂停，恢复时还原音量 |
| 系统睡眠 / 驱动重启 | 可能误暂停一次，冷却窗口限制为一次 |
| `localStorage` 不可用 | `try/catch` 回退为默认开启；关闭开关即完全恢复原行为，无需刷新 |
| Firefox / Safari 桌面 | 无 `sinkchange`，靠其余三类信号；不承诺 100% 覆盖 |
| 浏览器完全不暴露设备变化 | 退化为原行为（继续播放），属平台能力边界 |

纯 Web 无法直接读取「3.5mm 插头被拔出」这一物理事件，如需 100% 精确检测必须引入原生层（Electron / 客户端），当前架构下不做。

## 七、涉及文件

| 文件 | 职责 |
|------|------|
| `src/player.js` | 事件注册、`pauseForAudioDevice()` / `_clearDevicePause()`、`togglePause()` 与 `resetProgress()` 的状态清理 |
