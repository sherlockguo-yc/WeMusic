# 年度听歌总结 · 功能规格

> 定位：现状说明（改这个功能前必读）。需求动机与方案取舍见 `docs/需求文档/年度听歌总结.md`。
> 最后更新：2026-11-12

## 1. 它是什么

一个独立视图（不是「我的数据」里的 tab）：把某一自然年的听歌数据组织成 8 屏滚动叙事。入口是侧边栏「年度总结」（移动端底部 Tab 同名项）。

## 2. 入口与视图切换

| 位置 | 代码 |
|------|------|
| 侧边栏按钮 | `public/index.html` → `#navYearly` |
| 点击绑定 | `src/stats.js` → `initStats()` 里 `import('./yearly.js')` |
| 视图函数 | `src/yearly.js` → `openYearly()` |
| 历史恢复 | `src/main.js` → `restoreView()` 的 `view === 'yearly'` 分支 |
| 高亮态 | `src/playlist-ui.js` → `setActiveNav()` 的 id 列表（**漏加会导致侧边栏高亮错乱**） |

`openYearly()` 做三件事：`state.view = 'yearly'`、`setActiveNav('navYearly')`、`navPush('yearly')`，然后渲染到 `#main`。

滚动权交给页面自己：`body.yearly-mode #main { padding: 0; overflow: hidden; }`，由 `.yearly-scroll` 做 `scroll-snap-type: y mandatory`。退出清理在 `main.js` 的 `navPush()`（`if (view !== 'yearly') classList.remove('yearly-mode')`），与 `share-view` 同一套模式。

## 3. API

`GET /api/stats/yearly?yearOffset=0`（`server/routes/stats.js`，需登录）

- `yearOffset`：0 = 当前年（结束时间取「此刻」而非 12/31），1 = 去年，上限 10。
- 一次返回整页数据；翻年份重新请求，前端用自增 `seq` 丢弃陈旧响应。

响应字段（无数据时 `hasData: false`，其余为空）：

```
year, label, hasData
overview: { plays, sec, uniqueSongs, uniqueArtists, days, newSongs }
monthly:  [{ month: 1..12, plays, sec }]        // 固定 12 项，缺月补 0
topSongs: [{ name, singer, album, album_mid, play_count, total_sec }]  // 10
topArtists:[{ singer, singer_mid, play_count, total_sec }]             // 5
topAlbums: [{ album, singer, album_mid, play_count }]                  // 4
highlights: {
  bestDay:   { day: 'YYYY-MM-DD', plays } | null,
  streak:    { days, start, end },
  peakMonth: { month, plays } | null,
  lateNight: { hour: 0..4, plays } | null,
  repeatRate, skipRate, completion: { low, mid, high }
}
```

## 4. 数据口径

- 全部来自 `play_logs`，索引 `idx_play_logs_user(user_id, played_at)`。
- 日期分组统一用 `date(played_at/1000,'unixepoch','localtime')`（与上报时间一致，不用 UTC）。
- `topArtists` 复用 `aggregateArtists()`（按 `/、、,，&` 拆合唱，各自计满权重）+ `attachSingerMids()` 补头像。
- `topAlbums` 的 mid 用「组内第一个有效值」`MAX(CASE WHEN album_mid != '' AND album_mid GLOB '*[^0-9]*' THEN album_mid END)`，再经 `fillAlbumCoverMids()` 反查兜底（与月报一致）。
- `streak` 在 JS 里算（`computeStreak()`），不写递归 SQL。
- `completion` 只统计 `duration > 0` 的行，避免未知时长撑大分母。

**⚠ `MEANINGFUL_COND` / `SKIP_COND` 片段内含 `OR`，常量本身已带外层括号。** 拼进 `WHERE` 时不能再省这层括号：`AND` 优先级高于 `OR`，`WHERE user_id=? AND x OR y` 会退化成 `(user_id=? AND x) OR y`，`y` 那半段绕过用户过滤、把全库数据算进来。2026-11-12 之前 `newSongs` 就踩了这个坑（月报的「新歌发现」长期偏大）。

## 5. 前端结构（8 屏）

`src/yearly.js` 的 `screenHtml(data)` 一次生成全部屏：

1. 封面：年份大数字（渐变文字）、全年播放次数与时长
2. 数字：播放次数 / 累计时长 / 不同歌曲数 / 听歌天数 + 一行 aside（歌手数、新收歌曲）
3. 年度歌手：头号歌手头像 + Top 5 排行条
4. 年度歌曲：头号歌曲大卡片 + 2~6 名列表
5. 年度专辑：Top 4 封面墙（移动端 2×2）
6. 年度之最：单日最高 / 最长连续 / 最常月份 / 深夜时刻 4 张卡 + 跳过快/重复率/完播率
7. 月度趋势：12 根柱（CSS 百分比高度，非 canvas）
8. 人格收尾：`yearlyPersona()` 生成称号 + 「再看一遍」回顶

交互：
- `IntersectionObserver`（threshold 0.55，root 为 `.yearly-scroll`）给屏加 `.in` 触发入场动画，只加不撤，避免滚动抖动重播。
- 右侧圆点（移动端移到底部居中）点击 `scrollTo({ top: screen.offsetTop })`。
- 年份切换：`‹` 永远可点（上限 10 年），`›` 在 `yearOffset === 0` 时 disabled。

## 6. 边界与已知限制

- 该年无记录 → 只渲染一屏空态（`emptyHtml()`），无圆点翻页。
- 接口失败 → 「加载失败：xxx」+ 重试按钮。
- 没有收藏、没有专辑时对应屏内部留空，不隐藏整屏。
- 未做分享海报（本期范围外）；需要时组装 `posterData` 复用 `report.js` 的弹窗。
- 时间成本：`topAlbums` 缺 mid 时最多等 1.5s 反查（有 24h 缓存）。
