# 歌单导入

## 概述

音乐用户的歌单沉淀在多个平台，支持从外部平台导入歌单降低迁移壁垒。

## 数据流

```
用户粘贴分享链接 → POST /api/music/parse-playlist
  → 服务端解析链接 → 调用对应平台的歌单 API（Apple 为抓取公开页面内嵌数据，无需 token）→ 返回歌曲列表
  → 前端展示 → 用户确认 → 批量写入 songs 表 + 关联到歌单
```

## 已实现

- **QQ 音乐歌单导入**：解析分享链接（`https://y.qq.com/n/ryqq/playlist/...`），提取歌曲列表。（`POST /api/music/parse-playlist` → `server/services/qqmusic.js` → 调 QQ 音乐 `uniform_get_Dissinfo` 接口）
- **网易云音乐歌单导入**：解析分享链接（`https://music.163.com/playlist?id=...`），提取歌曲列表。（同上端点 → `server/services/netease.js` → 调网易云歌单 API）
- **Apple Music 歌单导入**：解析分享链接（`https://music.apple.com/cn/playlist/.../pl.xxx`），提取歌曲列表。（同上端点 → `server/services/apple.js` → 抓取歌单公开页面并解析内嵌数据：主数据源为 `serialized-server-data`，降级为 schema.org JSON-LD；无需 token / 登录。注意路由中 Apple 分支最先判断，防止 pl ID 内连续数字被 QQ/网易云兜底正则误吞）
- **JSON 文件导入/导出**：WeMusic 自身格式的备份与恢复。导出将当前歌单序列化为 JSON 文件下载，导入解析 JSON 并写入数据库。

## 封面补齐（album_mid 反查）

全项目封面 URL 只由 QQ 专辑 mid 拼出（`https://y.qq.com/music/photo_new/T002R{size}x{size}M000{album_mid}.jpg`）。外部平台导入的歌曲缺有效 QQ album_mid → 封面为空：

| 来源 | album_mid 原值 | 结果 |
|------|---------------|------|
| Apple Music 导入 | 空 | 封面为空 |
| 网易云导入 | 网易云自己的数字专辑 ID | 拼出 URL 404，封面同样为空 |
| QQ 音乐导入 / 搜索添加 | 真实 QQ 专辑 mid | 封面正常 |

**补齐机制**（两级，均不阻断导入）：

1. **导入时反查**：`parseApplePlaylist` / `parseNeteasePlaylist` 返回前，对缺有效 mid 的歌曲用「歌名 + 歌手」调 QQ 搜索接口（`fullSearch`）反查，命中则写入。并发 4 路、整体 20s 上限；单首失败/未命中保持原值。
2. **存量回填**：打开歌单页时前端检测到缺有效 mid → 调 `POST /api/playlists/:id/fill-album-mids` → 服务端反查并写回 DB（同歌单 10 分钟防重）；完成后原地刷新四宫格封面，并把新 mid 同步进正在播放的 queue（播放器封面即时生效）。

**匹配策略**（`pickAlbumMid`）：歌名精确匹配（忽略大小写）→ 优先歌手名命中的候选 → 否则取第一个精确匹配项；无精确匹配则放弃（宁可无封面，不张冠李戴）。实测 33 首 Apple 歌单命中 32/33（约 2.8s）。

## API 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/music/parse-playlist` | 解析外部歌单链接，返回歌曲列表预览 |
| POST | `/api/music/album-backfill` | 按 `[{sourceId, name, singer}]` 批量反查 album_mid（离线页存量回填） |
| POST | `/api/playlists/import` | 以歌曲列表新建歌单（JSON 备份导入 / 文件导入） |
| POST | `/api/playlists/:id/songs` | 将解析出的歌曲批量写入指定歌单 |
| POST | `/api/playlists/:id/fill-album-mids` | 补齐该歌单缺失封面的 album_mid（Apple/网易云存量歌曲） |
| GET | `/api/playlists/:id/export` | 导出指定歌单为 JSON 文件 |

## 边界条件

- 链接格式不合法 → 400 + 错误提示"无法从链接中解析出歌单 ID，请检查链接格式"
- 外部 API 超时/不可用 → 502 + 错误提示，建议用户稍后重试
- 歌单为空 → 预览页正常显示 0 首
- 部分歌曲解析失败（如歌曲已在平台下架） → 导入成功的部分，跳过的在日志中记录
- 重复导入同一歌单 → 写入时按「歌名__歌手」去重，重复项跳过（toast 提示跳过数量）
- JSON 文件格式不匹配 → 返回"文件格式不正确，请选择 WeMusic 导出的 JSON 文件"
- Apple Music：歌单不存在/未公开 → 502「歌单不存在或未公开」；页面结构变更且 JSON-LD 亦无法解析 → 502「解析失败，Apple Music 页面结构可能已变更」
- 封面反查：QQ 搜索超时（单首 8s）/ 未命中 → 该首 album_mid 保持原值，不影响导入与播放（歌名歌手精确匹配，不会配错歌）
- 封面反查导致的导入耗时增加：约 +3s / 33 首（并发 4 路实测），整体上限 20s
- 反查不到的差异：Apple 上的「单曲（- Single）」在 QQ 上常归到专辑，封面会显示 QQ 该专辑的图（与 Apple 的单曲封面可能不同）
- 存量回填防重：同一歌单 10 分钟内只尝试一次（避免 QQ 里没有的歌被反复查询）

## 已知限制

- QQ 音乐歌单解析依赖 `disstid`（从链接中正则提取），不支持加密/私有歌单
- 网易云歌单解析依赖公开 API，可能因网易云接口变动而失效
- Apple Music 歌单解析依赖页面 SSR 数据（未使用需 token 的 amp-api），Apple 页面改版可能导致解析失效；已设 JSON-LD 降级路径与明确报错兜底
- 封面反查依赖 QQ 音乐有对应歌曲：QQ 没有的歌（Apple 独占、冷门翻唱）仍无封面；反查失败不影响播放
- 不支持 Spotify 歌单导入（API 需要 OAuth 授权）
